Tread drive over Bluetooth

Started 2026-10-06 · Revision 2 (2026-10-06) — Pat settled the three open points (D7 to D9) · status: approved, ready for the build plan

In one paragraph

The spare badge rides on the tank base with no cable. A computer (the Mac for testing, later rocky-pi) sends it a small Bluetooth message: a speed for the left tread and a speed for the right. The badge turns that into the LEGO infrared signal the base already obeys. If the messages stop for any reason, the base stops. This first version covers the two treads only; motor boards on the I2C port are a later step.

How the pieces connect

Memory: where it goes and how we avoid running out

The chip has two kinds of memory. The large external memory (8 MB) holds the Python runtime and is not the problem. The small internal memory is what Bluetooth and infrared must use, and that is the tight one. The bars below show the internal memory left over after the rest of the firmware has started, which is about 102 KB.

The rules that keep us inside the edge

  1. Nothing new is created while driving. The drive service sets up everything it needs once at start-up and reuses it. No new background task, no growing lists.
  2. The badge reports its own free memory. The status it sends back includes the free amount now and the lowest it has ever been since power-on. The controller can see trouble coming.
  3. A floor of 6 KB. If free memory is below 6 KB when a controller asks to drive, the badge refuses, stays stopped, and says so in its status.
  4. Measure first. The first build step is to connect a controller and read those two numbers. If connecting alone drops free memory under the floor, the build stops there and I free memory before going on (the candidates are the Wi-Fi start-up attempt and the oversized main stack).
  5. Pass mark: ten minutes of driving with the lowest-ever figure still above 6 KB.

Each figure comes from a single start-up, so treat them as good to a kilobyte or two. The one unknown that matters is the cost of a live connection, and rule 4 settles it before anything else is built.

The Bluetooth messages

A second small service sits beside the existing mood service, with the same shape: one place to write commands, one place to read status. It uses the same 8-byte shared secret the mood service uses, so only your own controller can drive.

Drive command (11 bytes, written by the controller)

BytesMeaningRange
0–7Shared secretmust match, or the message is ignored
8Left tread speed, in tenths−70 to 70 (so 43 means speed 4.3); positive is forward
9Right tread speed, in tenths−70 to 70
10How long this command stays valid, in tenths of a second1 to 10 (one second at most)

The controller repeats the command about five times a second while it wants the base to move. Speeds of 0 and 0 mean stop now. Anything out of range is ignored and the base is left as it was.

Status (8 bytes, read by the controller)

ByteMeaning
0Flags: driving now · infrared ready · refused for low memory · last command rejected
1, 2Left and right speed currently being sent, in tenths
3Time left on the current command, tenths of a second
4Battery percent
5Free internal memory now, in quarter-kilobytes (36 means 9 KB)
6Lowest free internal memory since power-on, same unit
7Count of commands accepted, wrapping at 255

Stopping: the safety rule

Same rule as the brick body: a stop always wins, and silence means stop. There are three layers, each catching what the one before it misses.

Worked example

pf_ble_drive.py 4 4 1500        # forward about a foot
  → writes  [secret] 28 28 0A   five times a second for 1.5 s   (0x28 = 40 tenths)
  → badge sends left 4.36 (trim applied), right 4, as infrared every 90 ms
  → after 1.5 s the script writes  [secret] 00 00 01  and reads status:
     driving=no  battery=98%  free=8.5 KB  lowest=8.0 KB

How it will be tested

  1. On the Mac, no hardware: the signal maker produces the same frames as the tuned Python script for a table of speeds, including in-between ones.
  2. Badge on USB: connect by Bluetooth, read the memory figures (rule 4).
  3. Cable unplugged, base on the carpet: forward, back, both spins, and a quarter turn, matching today's results.
  4. Stop layers: kill the script mid-move (layer 1), switch the Mac's Bluetooth off mid-move (layer 2), cover the badge's emitter mid-move (layer 3). The base must stop each time within about a second.
  5. Ten minutes of mixed driving; lowest free memory stays above 6 KB.

Not in this version

  • Motor boards on the I2C port.
  • rocky-pi and the brain driving the base (follow-on, see D7).
  • Listening to the LEGO handheld remote.
  • Distances and angles ("forward 30 cm"). The base has no sensors, so those stay as timing on the controller side.
  • Any change to the face badge or its firmware.
